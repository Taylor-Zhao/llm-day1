# Day42 面试题整理（RAG / Agent / 评测 / 成本优化）

## A. RAG 方向

1. 问：为什么需要 RAG，而不是只做模型微调？
答：RAG 适合“知识频繁更新、需要可溯源”的场景，能把外部知识与生成解耦；微调更适合“固定风格/流程对齐”。两者可组合：RAG 负责新知识注入，微调负责表达与行为模式对齐。

2. 问：你如何做 chunking 策略选择？
答：以召回质量和上下文完整性为目标，比较 chunk size、overlap 对检索命中与最终回答质量的影响。通常先用中等 chunk + 小 overlap，再基于评测集迭代。

3. 问：混合检索（关键词 + 向量）有什么价值？
答：关键词检索擅长精确术语匹配，向量检索擅长语义召回；混合可降低单一路径盲区，提升稳定性，尤其在专业名词与自然语言混合查询场景。

## B. Agent 方向

1. 问：Agent 和普通工具调用有什么区别？
答：普通工具调用更像单步函数执行；Agent 具备多步规划、状态传递、失败恢复与结果汇总能力，适合复杂任务编排。

2. 问：Agent 如何避免“无限循环调用工具”？
答：设置最大步骤、最大重试次数、超时与回退路径；同时记录每步审计日志，出现异常时可中断并返回可解释的降级结果。

3. 问：为什么要保留 request_id 和审计日志？
答：为了可观测性和可追溯性。线上问题定位需要把请求、工具调用、错误码、耗时串成完整链路。

## C. 评测方向

1. 问：你为什么强调固定评测集？
答：固定评测集是可比性的前提。没有固定输入，任何“效果提升”都可能是样本漂移造成的假象。

2. 问：Day32 的质量分为什么是加权组合？
答：当前阶段快速落地优先，使用结构完整性和关键词命中率构成启发式指标，先建立自动化评估能力，再逐步引入人工标注或更强评测器。

3. 问：如果训练 loss 降了但线上回答变差，怎么解释？
答：训练 loss 只反映拟合训练分布，不等于业务质量。应回看评测集覆盖、提示词格式、推理参数与线上真实问题分布是否一致。

## D. 成本优化方向

1. 问：你做过哪些成本优化？
答：从模型、推理模式、调用策略三层优化：小模型 + LoRA、批处理/并发/量化对比、缓存与去重、按场景控制 max tokens。

2. 问：fp32 和 dynamic_int8 如何选？
答：fp32 稳定且适合基线；dynamic_int8 更偏 CPU 轻量加速与内存优化，是否收益需实测，且要评估精度折损。

3. 问：上线后你先看哪些指标？
答：先看成功率和错误码分布，再看 P95 延迟和 token 用量，最后看业务侧质量指标（比如通过率、人工反馈）。
